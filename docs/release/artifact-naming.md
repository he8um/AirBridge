# Artifact Naming Convention

## Workflow Artifact Names

Artifacts produced by the release workflow follow this pattern:

```
airbridge-<version>-<OS>
```

Where:

- `<version>` is the value of the `version` workflow input (e.g. `v0.1.0-alpha`)
- `<OS>` is the GitHub Actions `runner.os` value for the build matrix entry

### OS Values

| Matrix runner      | `runner.os` value | Example artifact name                   |
| ------------------ | ----------------- | --------------------------------------- |
| `macos-latest`     | `macOS`           | `airbridge-v0.1.0-alpha-macOS`          |
| `ubuntu-latest`    | `Linux`           | `airbridge-v0.1.0-alpha-Linux`          |
| `windows-latest`   | `Windows`         | `airbridge-v0.1.0-alpha-Windows`        |

---

## Artifact Contents

Each workflow artifact is a zip archive containing the contents of the Tauri bundle output directory:

```
apps/desktop/src-tauri/target/release/bundle/
```

Typical bundle outputs by platform:

| Platform | Bundle directory contents                          |
| -------- | -------------------------------------------------- |
| macOS    | `dmg/` — `.dmg` installer                         |
| Linux    | `appimage/` — `.AppImage`; `deb/` — `.deb` package |
| Windows  | `msi/` — `.msi` installer; `nsis/` — `.exe` setup |

The exact bundle formats depend on the Tauri configuration in `tauri.conf.json`. Formats may vary between Tauri versions.

---

## Version Naming

- Version values in artifact names match the release tag exactly: `v0.1.0-alpha`, `v0.1.0`, `v0.2.0-beta`, etc.
- The `v` prefix is always included.
- Pre-release identifiers (`-alpha`, `-beta`, `-rc.1`) follow the version number.
- No spaces, underscores, or dots in the OS segment of the artifact name.

---

## Checksums

Checksums are not automatically generated by the release workflow. Before publishing a GitHub release, generate SHA-256 checksums manually from the downloaded artifacts:

```bash
shasum -a 256 <artifact-file>
```

Include checksum values in the GitHub release body alongside the artifact download links.

---

## Naming After Extraction

When renaming extracted installer files for distribution, use the same version and OS convention:

```
airbridge-<version>-<os>.dmg
airbridge-<version>-linux-x86_64.AppImage
airbridge-<version>-windows.msi
```

The exact naming of extracted files is not enforced by the workflow — the convention above is recommended for consistency.
