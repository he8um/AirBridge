# AirBridge v0.1.0-alpha — Release Notes Draft

> This is a draft for internal review. Do not publish without final verification.

---

## Overview

AirBridge v0.1.0-alpha is the first public alpha release. It delivers the core backup and inspection workflows for Airtable bases. Restore write execution is present as a safety gate only — no Airtable data is written by restore operations in this version.

This release is intended for early testers who want to evaluate the backup and inspection capabilities and provide feedback before the full restore engine is enabled.

---

## What's New in v0.1.0-alpha

### Backup

- **Connection check** — verify a personal access token and inspect its permissions before running a backup.
- **Base selection** — list all accessible bases for a token and select one to back up.
- **Backup planning** — preview what will be backed up: tables, fields, record counts, and field compatibility classification.
- **Records export planning** — generate a table ordering plan that respects linked record dependencies.
- **Backup execution** — write a `.airbridge` package to a user-chosen local path.
  - Requires explicit file picker selection.
  - Requires the exact confirmation text `CREATE BACKUP` before execution.
  - Token is consumed per-operation and never stored.
  - Output path validation prevents path traversal, wrong extensions, and writes to existing directories.
  - Cancellation supported mid-job.

### Package Inspection

- **Inspection** — open any `.airbridge` file and review its contents without starting a restore.
- **Validation** — check manifest integrity, schema consistency, checksum validity, and restore compatibility.
- **Field compatibility report** — each field is classified as Restorable, Partially Restorable, Metadata Only, or Unsupported.
- Inspection is read-only: no files are extracted, no token required, no Airtable API calls.

### Restore (Planning Only — Writes Disabled)

- **Restore dry-run** — generate a restore plan preview from a package: tables, field compatibility, record counts, ordering, and warnings. Read-only; no token required.
- **Restore schema creation plan** — generate a full schema creation order from a dry-run result: table creation steps (ordered to satisfy linked record dependencies), field creation steps, deferred linked record fields, manual-action fields, and a linked record dependency graph. Read-only; no token required; no Airtable tables or fields are created.
- **Restore record import plan** — generate a complete record import batch plan from a dry-run result and schema plan: per-table batch counts (batch size 10), field import policies (Include / DeferToLinkedRecordPass / MetadataOnly / Skip), linked record second-pass update plans, attachment metadata policies, old-to-new record ID mapping strategy, per-table checkpoint plans, and a retry policy. Read-only; no token required; no Airtable records are created.
- **Restore execution gate** — validates all preconditions (inspection status, dry-run plan, target mode, token, confirmation text). When all gates pass, the command returns `readyButDisabled` — no Airtable writes are made.
- The write engine will be enabled in a future release. All planning steps above are safe to run in any order; none modifies Airtable data.

### Local Activity History

- **Job history** — the Reports page displays a summary of recent operations (connection checks, backup jobs, restore operations) with status, timestamps, and file counts.
- History items contain safe summaries only: no tokens, no full file paths, no record payloads, no attachment URLs.
- History is stored in memory for the current session only and is cleared on application restart.

### Release Build Workflow

- **Release workflow** — a `workflow_dispatch`-only GitHub Actions workflow builds the Tauri application on macOS, Linux, and Windows and uploads platform artifacts. No release is created or published automatically.

## What Is Not Included in This Release

- Restore write execution (deferred — gate is complete, write engine is not enabled).
- Token/credential persistence (tokens are entered per-operation).
- Background job history or streaming progress.
- Attachment file download (attachment metadata and URLs are backed up; file bytes are not downloaded).
- Restore into non-empty bases.
- Merge or overwrite restore workflows.
- Automations, interfaces, or sharing settings backup/restore.
- Exact system field value restore (created time, modified time, created by, last modified by).

## Security and Privacy

- No telemetry, analytics, or crash reporting.
- Tokens are accepted as input per-operation and discarded immediately after use. Nothing is written to disk, memory, or any persistent store.
- Backup packages may contain sensitive Airtable data. Treat `.airbridge` files like database exports.
- No attachment file bytes are downloaded or stored — only metadata and URLs at the time of backup.
- No Airtable data is modified by inspection, validation, dry-run, or restore execution (which is disabled).
