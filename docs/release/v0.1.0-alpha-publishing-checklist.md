```bash
npm --prefix apps/desktop run typecheck

npm --prefix apps/desktop run rust:test

# Frontend build
npm --prefix apps/desktop run build

# Full check suite
npm --prefix apps/desktop run check

# Root-level check

```

**Known local PATH issue:** If `npm run check` or `npm --prefix apps/desktop run rust:fmt:check` fails with `sh: cargo: command not found`, this is a pre-existing issue where npm's script environment does not include `~/.cargo/bin`. Run the equivalent direct cargo commands instead:

```bash
export PATH="$HOME/.cargo/bin:$PATH"
cargo fmt --manifest-path apps/desktop/src-tauri/Cargo.toml -- --check
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
```

All three must pass. The PATH issue is local/pre-existing and does not indicate a code failure. Document it in the release if it persists. Do not publish if any real check fails.

**Expected results:**
- Frontend tests: 1533 passing
- Rust unit tests: 2561 passing, 5 ignored (the 5 live sandbox harnesses)

## 3. Prohibited Terms Scan

```bash
grep -RniE 'claude|anthropic|chatgpt|openai|ai-generated|ai assisted|ai-assisted|agent|llm|prompt|co-authored|generated with|generated by' \
  . \
  --exclude-dir=.git \
  --exclude-dir=node_modules \
  --exclude-dir=target \
  --exclude-dir=dist \
  --exclude-dir=build
```

**Pass condition:** No hits in source files (`.rs`, `.ts`, `.tsx`), docs (`.md`), or config files (`.json`, `.toml`).

Known benign matches that must remain unchanged:
- Scan command text quoted in QA doc checklists (not a prohibited usage).
- `generated by` in technical descriptions (e.g., "Generated by `warnings_for_schema_steps()`").
- `package-lock.json` npm integrity hash strings.
- `vi.clearAllMocks()` in test files (Vitest utility).

**Stop if:** Any hit in source or doc content is not one of the known benign matches above.

## 5. Artifact Preparation Plan

Artifacts are produced by the `workflow_dispatch`-only GitHub Actions release workflow (`release.yml`). Do not build release artifacts locally for distribution.

### Step 1: Trigger the release workflow

1. Go to **Actions → Release** on GitHub.
2. Click **Run workflow**.
3. Set `version` to `v0.1.0-alpha`.
4. Click **Run workflow**.

The workflow will:
- Run quality gates on macOS, Linux, and Windows.
- Build the Tauri application for each platform.
- Upload artifacts as workflow run artifacts only.
- Not create a GitHub release automatically.

### Step 2: Download and inspect artifacts

After the workflow completes, download and verify each artifact.

## 6. Checksum Plan

Generate SHA-256 checksums for every artifact file before attaching to the GitHub release.

```bash
# macOS
shasum -a 256 airbridge-v0.1.0-alpha-macos.dmg

# Linux
shasum -a 256 airbridge-v0.1.0-alpha-linux-x86_64.AppImage
shasum -a 256 airbridge-v0.1.0-alpha-linux-x86_64.deb

# Windows
shasum -a 256 airbridge-v0.1.0-alpha-windows.msi
shasum -a 256 airbridge-v0.1.0-alpha-windows.exe

# Or in one pass (from the directory containing all artifacts):
shasum -a 256 airbridge-v0.1.0-alpha-* > checksums.txt
cat checksums.txt
```

- Store the output in `checksums.txt`.
- Attach `checksums.txt` to the GitHub release alongside the artifacts.
- Do not include local absolute paths or secrets in checksum output.
- Verify checksums after upload by re-downloading and re-running `shasum -a 256 --check checksums.txt`.

## 7. Signing and Notarization Status

**Current status: Unsigned alpha.**

This release artifact is not notarized (macOS) and not code-signed (Windows).

**macOS:** Gatekeeper will warn that the application is from an unidentified developer. Testers must right-click → Open to bypass the warning on first launch. Document this in the GitHub release body.

**Windows:** Windows SmartScreen will warn that the publisher is unknown. Testers must click "More info" → "Run anyway". Document this in the GitHub release body.

**Linux:** No signing requirement for AppImage or deb.

This is acceptable for a public alpha. Signing and notarization should be configured before any general public distribution or stable release. See [code-signing-and-notarization.md](code-signing-and-notarization.md).

## 10. Restore Safety Reminders

The following must be true at the time of publishing. Verify each before creating the GitHub release:

- [ ] **App runtime restore execution is disabled.** `evaluate_write_gate()` always returns `Disabled/DisabledByProductPolicy`. No enabled branch exists.
- [ ] **No UI/Tauri live restore execution surface exists.** No Tauri command, no UI button, and no TypeScript path exposes live Airtable restore writes.
- [ ] **Live sandbox harnesses are `#[ignore]` by default.** Standard `cargo test` does not run them. They are not reachable from normal app runtime. They require explicit env var opt-in and a disposable sandbox Airtable base.
- [ ] **`RestoreWriteEngineStatus::Succeeded` does not exist in the type system.** A restore cannot succeed in this version.
- [ ] **Attachment binary handling is disabled.** No binary download, upload, URL fetch, or file transfer occurs.
- [ ] **Attachment metadata captured at backup time only.** URLs may expire; file bytes are not stored.
- [ ] **User-facing restore execution requires future product/security approval.** No approval has been granted. Do not imply it has.
- [ ] **Release notes do not claim "stable restore", "complete restore", "production restore", "one-click restore", "perfect clone", or "attachments restored".**

## 12. Rollback Plan

### If the tag was created locally but not pushed

```bash
git tag -d v0.1.0-alpha
```

### If the tag was pushed to remote by mistake

```bash
git push origin :refs/tags/v0.1.0-alpha
```

### If a GitHub release draft was created in error

- Go to **Releases** on GitHub.
- Open the draft release.
- Click **Edit** and set it back to **Draft**, or click **Delete this release**.
- Deleting a release does not delete the tag. Delete the tag separately if needed.

### If the release was published (not just drafted) in error

- Immediately convert back to Draft on the Releases page.
- Communicate to any testers who may have downloaded the artifacts.
- Investigate the issue before re-publishing.
