# Restore Schema Creation Planning

## Overview

The restore schema creation planner converts a restore dry-run plan into a safe, ordered schema creation plan. It classifies every field in every table and produces a step-by-step plan for table creation, field creation, deferred linked fields, and manual-action fields.

**No Airtable API calls are made.** No token is required. No files are extracted or written.

## Input

`RestoreSchemaPlanRequest`:

| Field | Description |
|---|---|
| `package_filename` | Filename only (not a path). Echoed in the result for identification. |
| `dry_run_status` | Gate check — must be `"ready"` or `"readyWithWarnings"`. |
| `target_mode` | `NewBase` or `EmptyExistingBase`. |
| `target_base_name` | Optional. |
| `tables` | Table and field data derived from the dry-run plan. |

There is no `token` field. Token-free by design.

## Output: RestoreSchemaPlan

| Field | Description |
|---|---|
| `filename` | Filename only — never a path. |
| `status` | `Ready`, `ReadyWithWarnings`, or `Blocked`. |
| `table_steps` | Ordered list of tables to create. |
| `field_steps` | Fields to create directly (CreateDirectly, CreateWithAdjustment, MetadataOnly). |
| `deferred_steps` | Linked record fields deferred until all tables exist. |
| `manual_action_fields` | Fields requiring manual action (collaborators, formula, rollup, lookup). |
| `dependency_graph` | Linked record dependency edges and circularity flag. |
| `warnings` | Per-table warnings (attachment metadata, deferred links, unsupported fields). |
| `errors` | Blocking errors (DRY_RUN_BLOCKED, NO_TABLES). |
| `no_changes_made` | Always `true`. |

## Field Classification

`classify_field_for_schema()` maps field types to `RestoreFieldCreateClassification`:

| Classification | Field Types |
|---|---|
| `CreateDirectly` | singleLineText, multilineText, email, url, phoneNumber, number, currency, percent, rating, checkbox, date, dateTime, duration, barcode, singleSelect, multipleSelects |
| `MetadataOnly` | multipleAttachments, autoNumber, createdTime, lastModifiedTime, count |
| `DeferUntilTablesExist` | multipleRecordLinks |
| `Unsupported` | formula, rollup, lookup |
| `ManualActionRequired` | singleCollaborator, multipleCollaborators, createdBy, lastModifiedBy, unknown types |

## Table-First Ordering

All table creation steps are planned before field creation steps. Linked record fields are always deferred to after all tables are created.

## Dependency Graph

`build_dependency_graph()` reads `multipleRecordLinks` fields to construct a graph of linked record dependencies:

- Each edge represents a link from a source table to a target table.
- `remapping_required: true` on every edge (record IDs must be remapped from backup IDs to restored IDs).
- Simple circularity detection: if any edge has `source_table_id == target_table_id` (self-link).

## Gate Check

If `dry_run_status` is not `"ready"` or `"readyWithWarnings"`, the planner returns immediately with `status: Blocked` and error code `DRY_RUN_BLOCKED`. If `tables` is empty, it returns `NO_TABLES`.

## Warnings

Generated by `warnings_for_schema_steps()`:

| Code | Trigger |
|---|---|
| `ATTACHMENT_METADATA_ONLY` | Any `multipleAttachments` field in the table |
| `LINKED_FIELDS_DEFERRED` | Any `multipleRecordLinks` field (deferred count > 0) |
| `UNSUPPORTED_FIELDS_REQUIRE_MANUAL_RECREATION` | formula/rollup/lookup count > 0 |
| `MANUAL_ACTION_REQUIRED` | Collaborator field count > 0 |

## Safety Properties

- No Airtable API calls.
- No token in request or result.
- No file I/O (all data from in-memory request).
- No full path in result (filename only).
- `no_changes_made` always `true`.
- No "succeeded" status anywhere in the result.

## Module Layout

```
src-tauri/src/restore/
  schema_plan.rs          — model structs and enums
  schema_steps.rs         — classify_field_for_schema, step builders
  schema_dependencies.rs  — build_dependency_graph
  schema_warnings.rs      — warnings_for_schema_steps
  schema_planner.rs       — create_schema_plan orchestrator + tests
```

## TypeScript Surface

- Types: `RestoreSchemaPlan`, `RestoreSchemaPlanRequest`, `SchemaPlanTableInput`, `SchemaPlanFieldInput`, `RestoreTableCreationStep`, `RestoreFieldCreationStep`, `RestoreDeferredFieldStep`, `RestoreManualActionField`, `RestoreLinkedDependencyStep`, `RestoreSchemaDependencyGraph`, `RestoreSchemaWarning`, `RestoreSchemaError`, `RestoreSchemaPlanStatus`, `RestoreFieldCreateClassification` — all in `backend/types.ts`.
- Command bridge: `createRestoreSchemaPlan()` in `backend/commands.ts`.
- Service method: `createRestoreSchemaPlan()` in `AirBridgeService`.
- UI: `RestoreSchemaPlanPanel.tsx` — generates and displays the plan, with `data-testid` attributes on all key elements.
