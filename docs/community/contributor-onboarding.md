# Contributor Onboarding

## Purpose

New contributors should start with documentation, small issues, test fixtures, UI improvements, or compatibility matrix updates.

## Standard process

1. Confirm the request is in project scope.
2. Check for sensitive data.
3. Apply labels.
4. Ask for missing information if needed.
5. Link related issues or documentation.
6. Decide whether to accept, defer, reject, or close.

## Label examples

```text
type: bug
type: feature
type: docs
type: compatibility
area: backup
area: restore
area: api
area: ui
area: packaging
status: needs triage
status: accepted
status: blocked
priority: high
priority: medium
priority: low
```

## Safety note

Users must not be asked to share tokens, private records, or unredacted backup packages in public issues.
